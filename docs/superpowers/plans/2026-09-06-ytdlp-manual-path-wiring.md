# yt-dlp 手動パス設定の配線修正 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 設定画面の「yt-dlp パス」欄に入れた値が、実際の yt-dlp 検出（情報表示・更新確認・フォーマット取得・ダウンロード・スケジュール実行）で最優先に使われるようにする。

**Architecture:** バックエンドを唯一の真実の源にする。各コマンドは cookie 設定と同じ流儀で SQLite の `settings` テーブル（キー `ytdlp_path`）を読み、`detect_binary` に渡す。未配線だったメモリ上の `state.ytdlp_path` と Tauri コマンド `set_ytdlp_path` は撤去する。フロントはパス変更後に情報パネルを再検出し、失敗理由を表示する。

**Tech Stack:** Rust (Tauri v2, rusqlite, tokio, which, dirs), Vue 3 Composition API + TypeScript + Pinia + vue-i18n, vitest + @vue/test-utils (導入済み・テストファイルはまだ0件)

## Context

- 症状: homebrew 版 yt-dlp を削除すると「見つからない」エラー。設定欄に `~/.anyenv/envs/pyenv/shims/yt-dlp` を入れても無視され、再インストール後は常に `/usr/local/bin/yt-dlp` が採用される。
- 根本原因: `AdvancedSettings.vue:83` は `updateSetting('ytdlp_path', …)` → `set_setting` で DB に保存するだけ。一方 `binary::detect_binary(manual_path)` は `state.ytdlp_path`（`state.rs:30` で `None` 初期化）を読み、これを更新する `set_ytdlp_path` コマンド（`commands/settings.rs:7`）はフロントのどこからも呼ばれていない。DB の `ytdlp_path` を読む Rust コードも無い。初期コミット `b86c6b9` からこの状態。
- 副次的問題: `binary.rs` の `get_version` が終了コードを見ておらず、実行に失敗したバイナリでも空文字バージョンで「成功」扱いになる。
- 意図した仕様: `detect_binary` の docstring「manual path > system PATH > well-known paths > bundled」。UI ヒント「『auto』で自動検出、またはフルパスを入力」。
- 環境メモ（ユーザー実機）: Intel Mac。GUI 起動時の PATH は `/usr/bin:/bin:/usr/sbin:/sbin` のみ。pyenv 版 yt-dlp の実体は `/Users/annrie/.anyenv/envs/pyenv/versions/3.12.1/bin/yt-dlp`（2026.06.09）。deno / ffmpeg は `installed_on_request` なので homebrew の yt-dlp を消しても残る。

## 設計上の決定と注意（コードで検証済み）

- **手動パスは fail-fast**: 存在しない・実行できないパスが設定されていると、全コマンド（スケジュール実行含む）が「Manual yt-dlp path not found: …」等で失敗する。従来は黙って無視していたが、これが docstring どおりの仕様。UI はそのエラー文をそのまま表示する。
- **`resolve_binary` は `state.db` をスコープ内でロックして即解放する**。呼び出し側が `state.db` ロックを保持したまま呼ぶとデッドロックするため禁止。6箇所の呼び出し元はいずれもロック非保持（`resume_download` は直前で `drop(db)` 済み、`formats.rs` は検出後に DB を読む）ことを確認済み。
- **他に yt-dlp を解決する箇所は無い**: `scheduler.rs` と `images/` は `download.rs` の関数を経由する。`Command::new` の直接呼び出しは ffmpeg / osascript 等のみ。
- **`set_ytdlp_path` の参照は5箇所のみ**（`build.rs`、`capabilities/default.json`、`permissions/autogenerated/set_ytdlp_path.toml`、`commands/settings.rs`、`lib.rs`）。`gen/schemas` は gitignore 済みの生成物。`permissions/autogenerated` は 73 ファイルが git 管理下にあり `build.rs` の一覧より多い＝古い生成物は自動では消えないので、toml は手で削除する。
- **`AppState` の構築は `lib.rs:41` の1箇所だけ**。フィールド削除でテストや他モジュールは壊れない。
- **CI（`.github/workflows/validate.yml`）は `pnpm build` のみ**。`cargo test` と `vitest` はローカルが唯一の関門。新規テストファイルは `tsconfig` の `include` に入るため `vue-tsc --noEmit` で型検査される。
- 新しい依存は追加しない（`dirs` は既存依存、`@vue/test-utils` / `happy-dom` / `vitest` は導入済み）。
- **設計レビュー（Plan エージェント）での追加決定**: (1) 解決ヘルパーは `commands` 間依存を避けて `AppState::resolve_ytdlp_binary` にする。(2) `useYtdlp.loadInfo` は失敗時に `info` を `null` にしないと古い検出結果が表示され続ける。(3) `DownloadDialog` の「yt-dlp をインストール」ボタンは自動検出失敗のときだけ出す。手動パス起因のエラーで同梱版を入れても手動パスが優先されるため解決せず、今回の配線で初めて到達可能になる罠だった。(4) `install_ytdlp` の戻り値 `managed_by` を「bundled」固定にしない。

```rust
/// Normalize the raw `ytdlp_path` setting value.
/// `None`, "auto", empty, or whitespace-only mean auto-detect. A leading "~/" is expanded.
pub fn manual_path_from_setting(raw: Option<&str>) -> Option<String> {
    let trimmed = raw?.trim();
    if trimmed.is_empty() || trimmed == "auto" {
        return None;
    }
    if let Some(rest) = trimmed.strip_prefix("~/") {
        if let Some(home) = dirs::home_dir() {
            return Some(home.join(rest).to_string_lossy().to_string());
        }
    }
    Some(trimmed.to_string())
}
```

`get_version` を置き換え:

```rust
fn get_version(path: &PathBuf) -> Result<String, String> {
    let output = Command::new(path)
        .arg("--version")
        .output()
        .map_err(|e| format!("Failed to run yt-dlp at {}: {}", path.display(), e))?;
    if !output.status.success() {
        let stderr = String::from_utf8_lossy(&output.stderr).trim().to_string();
        return Err(format!(
            "yt-dlp at {} exited with {}: {}",
            path.display(),
            output.status,
            stderr
        ));
    }
    let version = String::from_utf8_lossy(&output.stdout).trim().to_string();
    if version.is_empty() {
        return Err(format!("yt-dlp at {} returned an empty version", path.display()));
    }
    Ok(version)
}
```

```rust
    /// Settings-table key holding the user's manual yt-dlp path ("auto" = auto-detect).
    pub const YTDLP_PATH_SETTING_KEY: &'static str = "ytdlp_path";

    /// Resolve the yt-dlp binary for a command: read the manual path from the settings DB
    /// under a scoped lock, then run detection (manual > PATH > well-known > bundled)
    /// off the async runtime because it spawns `yt-dlp --version`.
    /// Callers must not hold `self.db` while awaiting this.
    pub async fn resolve_ytdlp_binary(&self) -> Result<YtdlpBinary, String> {
        let raw = {
            let db = self.db.lock().await;
            queries::get_setting(&db, Self::YTDLP_PATH_SETTING_KEY).ok().flatten()
        }; // db lock dropped here
        let manual = binary::manual_path_from_setting(raw.as_deref());
        tokio::task::spawn_blocking(move || binary::detect_binary(manual.as_deref()))
            .await
            .map_err(|e| format!("Task error: {}", e))?
    }
```
